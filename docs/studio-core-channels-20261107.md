## حدود واجهات API والصلاحيات

هذه واجهة **محلية موثوقة** تعتمد `127.0.0.1` من إعداد Vite، وليست خدمة متعددة المستخدمين تملك تسجيل دخول أو تفويضًا حسب الشخص. اختيار قناة أخرى عبر `?channel=` يظل متاحًا للمستخدم المحلي المصرّح؛ لم نُنشئ نظام صلاحيات جديدًا أو نفتح الخادم للشبكة. يجب مراجعة أي تغيير لاحق في `host` أو proxy/مشاركة المنفذ قبل تسميته API آمنًا للاستخدام الخارجي.

الاعتمادات والإقرار بالمشاهد وملفات التلاوات وإدارة دورة Master مسؤولية الفروع المستقلة؛ تغييرات هذا الفرع لا تمنح صلاحية اعتماد ولا تعطل بواباتها.

3. اختبر API فعليًا على منفذ محلي غير إنتاجي: `/api/channels` و`/api/episodes?channel=<id>` للقنوات الثلاث، ثم PUT/GET للهوية والتقويم والأفكار على **بيانات اختبار** فقط، وراجع نتائج القنوات الأخرى قبل/بعد.
4. افحص سلامة استعادة العمل بعد إعادة تشغيل نسخة اختبارية وانقطاع كتابة محاكى؛ افحص `plan.json` و`channel.json` و`.env` دون لمس حلقات الإنتاج.

6. تأكد من عدم تعارض واجهة الإدارة أو عزل الرندر أو محرك الاعتمادات مع الفروع الموازية بعد جمعها؛ اختبر SHA الدمج مجددًا.
7. أعِد معاينة `GitHub Actions`؛ الفشل قبل إنشاء خطوات CI **لا يُعد** فشلًا اختباريًا ولا نجاحًا اختباريًا.
