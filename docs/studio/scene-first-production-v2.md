# Studio — عقد الإنتاج المعتمد الجديد V2: المشهد بالصوت والصورة

**قرار صاحب المشروع:** 7 نوفمبر 2026. **الحالة التنفيذية:** مواصفة معمارية معتمدة كاتجاه وشرط قبول جديد، **وليست تنفيذًا برمجيًا ولا موافقة نشر**. المرجع: PR #78، وتوزيع العمل على #71 و#73 و#74 و#76 و#77 و#79 و#80.

> **هذه الوثيقة تحل محل ترتيب المراحل الست القديم كأساس التطوير والتقييم.** تبقى الملفات السابقة ونتائج اختبار 726/726 دليلاً لسلامة ما اختُبر حينها، لكنها ليست اختبارًا لمحرك V2. لا يجوز دمج/نشر/الترحيل التلقائي اعتمادًا على تلك النتيجة.

## 1. هدف المنتج والمستخدم

- مستخدم Studio **شخص واحد**. الشاشة اليومية يجب أن تكون بسيطة: **الحلقات، القنوات، المكتبة، الإعدادات**. تبقى السجلات، البصمات، تفاصيل CI والرندر والتحقق المتقدم خلف «تفاصيل متقدمة»، لا واجهة تشغيل يومية.
- **وحدة الإنتاج/الإصلاح/المراجعة/الاعتماد = مشهد صوتي مرئي مكتمل**: الصورة والحركة والصوت والتزامنهما معًا، لا صوت منفصل يكتسب موافقة ملزمة للحركة لاحقًا.
- الموافقة البشرية صريحة ومحددة الإصدار، وفي موضعها. **المرحلة التالية لا تتحرر بواسطة نتيجة اختبار، أو وجود ملف، أو فتح صفحة**.
- تجميع المشاهد ثم مشاهدة الحلقة كاملة عند 1× واعتماد **بايتات Master النهائية** قرارات مستقلة لا تُستبدل باعتمادات المشاهد.

## 2. خطوات المؤلف من الفكرة إلى النشر (التسلسل الظاهر)

1. **الفكرة والسكريبت الأولي:** الموضوع، الهدف، الجمهور، الأسلوب، هيكل الحلقة.
2. **مراجعة تحريرية:** المقدمة، التدرج، السرد، الإيقاع، التشويق والوضوح.
3. **تدقيق علمي/لغوي/شرعي:** المصادر، الحقائق، التواريخ، الأسماء، الاقتباسات والآيات والأحاديث بحسب المحتوى، مع توثيق ما يتطلب أهل اختصاص. لا تفترض آلية تقنية أنها فتوى أو حكم شرعي.
4. **تثبيت النص المرجعي:** إصدار ونص أصلي وبصمة من بايتات المصدر، وسجل موافقة؛ لا تُعدّل النسخة المثبّتة بصمت.
5. **التشكيل والنطق:** ملف مشتق مرتبط بمرجع النص الأصلي مع تشكيل ونطق الأعلام، الوقفات، مواضع التشديد والإلقاء. تغيّر المعنى/الألفاظ يعيد الخطوة 4.
6. **نبرة كل مشهد:** السرعة والانفعال والتوقف والطبقة الصوتية واللغة، ثم قرار المالك قبل الإنتاج.
7. **اعتماد Storyboard PDF:** وثيقة إخراج لكل المشاهد وتكوينها وتوقيتها التقديري ورقم نسختها؛ الاعتماد على المضمون الحالي، لا مجرد توليد PDF.
8. **دورة المشاهد بالتتابع:** إنتاج المشهد الأول بصوته الفعلي وتركيبه داخل الفيديو ومراجعته وتصحيحه واعتماده؛ بعدها يُفتح الإنتاج النهائي للمشهد التالي، وهكذا. **يمكن تجهيز الأصول/الرسومات/عينات غير نهائية للمشاهد المقبلة مسبقًا** دون تجاوز بوابة الإنتاج النهائي.
9. **التجميع:** وصل المشاهد المعتمدة بالترتيب، الانتقالات، توحيد مستوى الصوت والإيقاع، نسخة معاينة حلقة متصلة.
10. **المراجعة الكاملة وMaster:** مشاهدة متصلة عند السرعة الطبيعية 1×، معالجة مشاكل الانتقالات والإيقاع، ثم إنتاج/فحص Master واعتماد الملف النهائي نفسه ببايتاته.
11. **النشر:** التحقق من الحقوق والبيانات، وبصمة Master والإصدارات المعتمدة، ثم إذن نشر منفصل. لا نشر تلقائي.

لا يتحول هذا إلى 11 تبويبًا: الشاشة تعرض **الخطوة الحالية والإجراء التالي**، وخلفها محرك مراحل أدق.

## 3. نموذج حالات المحرك المستهدف — لا نعيد تسمية القديم فقط

**خط إنتاج الحلقة داخليًا:**
\`editorial → script_locked → storyboard_locked → scene_cycle → assembly_review → master_approved → publish\`.

- \`editorial\`: مراجعة الفكرة والسكريبت/المصادر والتشكيل والنبرة، مع **قرارات فرعية مستقلة قابلة للتدقيق**.
- \`script_locked\`: النسخة المرجعية من النص مثبتة، مع بصمة/epoch ومراجعات المحتوى الحالي.
- \`storyboard_locked\`: كل مواصفات المشاهد وPDF الحالي مراجعة ومقبولة.
- \`scene_cycle\`: سجلات المشاهد المصورة الصوتية مستقلة، **لكن حارس ترتيبها مشترك**.
- \`assembly_review\`: تجميع اللقطات المعتمدة ومشاهدة الحلقة كاملة عند 1×.
- \`master_approved\`: اعتماد ملف Master النهائي نفسه وحقوقه وفق SHA-256 وبصمة تغيّر البايتات.
- \`publish\`: تنفيذ مستقل بعد تحقق جميع القيود على الخادم عند لحظة الإرسال.

**حالات كل مشهد (ليست حالة الصوت وحده):**
\`draft | prepared | producing | in_review | changes_requested | approved | needs_reapproval\`.

تاريخ الإصلاحات والاعتمادات **لا يُمحى**؛ التغيير بعد الاعتماد يخلق إصدارًا جديدًا بحالة \`needs_reapproval\`. لا يتحول المشهد إلى \`approved\` بمجرد اكتمال الرندر.

### حراس القرارات والعمليات

| الإجراء | شرط الخادم الإلزامي |
| --- | --- |
| تثبيت النص/Storyboard | مراجعات المصدر والتدقيق الحالي والقرار الصريح وفق fingerprint |
| تحضير أصل للمشهد القادم | ممكن بعد التحقق من ملكيته؛ لا ينتج اعتمادًا أو ملفًا للنشر |
| إنتاج **المشهد النهائي رقم N** | تثبيت النص/Storyboard الحاليين + كل مشهد قبله معتمد ببصمته الحالية + الهوية والصلاحية |
| عرض المشهد للمراجعة | فيديو صوتي حقيقي قابل للتشغيل، مزامنة وفحوص مشهد؛ لا يكفي MP3 منفصل أو صورة |
| اعتماد المشهد N | مشاهدة/استماع الملف المركب الحالي + فحوص النص/النطق/العناصر/الصوت/الحقوق/المزامنة + بصمات مطابقة + قرار مالك حقيقي |
| إنتاج المشهد النهائي N+1 | جميع المشاهد السابقة، ومنها N، معتمدة حاليًا |
| تجميع حلقة | كل المشاهد المطلوبة معتمدة حاليًا، نسخة كل مشهد مطابقة |
| اعتماد مراجعة الحلقة | معاينة صوت وصورة متصلة كاملة ومشاهدة صريحة عند 1× مع بصمة للنسخة |
| اعتماد Master | الجودة والحقوق ودليل المشاهدة وSHA-256 للـMP4 النهائي نفسه |
| نشر/حزمة مشتقات | Master المعتمد نفسه + فحص متزامن عند الإرسال؛ مشتقات 9:16 المتغيرة بصريًا تحتاج مراجعة صريحة لنسختها |

**اختلاف مهم:** تفصل سياسة V2 «الصوت الداخلي للمشهد» عن الصوت المنفصل للحلقة، وتحظر اعتمادًا إجماليًا للصوت يمنح تصريحًا عامًا للإنتاج؛ يمكن أن توجد أدوات توليد/تفريغ/تحسين صوت، لكنها جزء من إنتاج المشهد لا بوابة قبول نهائية مستقلة.

## 4. عقد بيانات مشهد V1 (تصميم قبل التنفيذ)

هوية العزل: \`{channelId, episodeDir, sceneId}\` بعد تحقق صارم من المسارات؛ لا يمكن للمتصفح اختيار مسار ملفات حقيقي. رقم المشهد جزء من **قائمة ترتيب مثبتة** داخل Storyboard. إعادة الترتيب تتطلب مراجعة التبعيات.

\`\`\`ts
type SceneReviewStatus =
  | "draft" | "prepared" | "producing" | "in_review"
  | "changes_requested" | "approved" | "needs_reapproval";

type SceneArtifact = {
  version: string; sha256: string; epoch: string;  // epoch يمنع إحياء موافقة قديمة عند رجوع البايتات
};

type SceneApprovalRecord = {
  sceneId: string;
  status: SceneReviewStatus;
  scriptRef: SceneArtifact;           // النص الأصلي الثابت + المصدر
  vocalizedRef: SceneArtifact;        // التشكيل والنطق والوقفات
  toneRef: SceneArtifact;             // توجيه الأداء
  boardRef: SceneArtifact;            // تكوين Storyboard المعتمد لهذا المشهد
  visualAssetsRef: SceneArtifact;     // الأصول والمواد المستخدمة فعليًا
  narrationRef: SceneArtifact;        // صوت الراوي أو تلاوة بشرية موثقة
  syncRef: SceneArtifact;             // التزامن والكلمات/اللقطات
  avFileRef: SceneArtifact;           // بايتات فيديو المشهد المركب القابل للمشاهدة
  rightsRef: SceneArtifact;           // إثبات الحقوق المرتبط بالوسائط المستخدمة
  approval?: {
    ownerId: string; at: string;
    reviewedAvSha256: string; expectedFingerprint: string;
    evidenceRefs: string[]; eventSeq: number;
  };
};
\`\`\`

هذا **عقد تصميمي غير منفذ**. يمكن فصل الـmanifest عن سجل القرارات الموقّع في التطبيق؛ لا تُقبل قيم \`ownerId\`، \`status\`، \`evidenceRefs\`، \`sha256\` أو \`epoch\` المرسلة من العميل كأدلة. الخادم يستخرجها من الملفات والسجلات الموثوقة ويوقع قرار المالك؛ يحتفظ بالملاحظات المرتبطة بزمن \`mm:ss\` أو \`sceneElementId\` أو كليهما.

**مقترح التخزين:** \`channels/<channel>/episodes/<episode>/scene-approvals.v1.json\` وسجل أحداث موقع/مغلق للكتابة عبر القفل الذري؛ أو تخزين مشهد معزول تحت \`scenes/<sceneId>/\` بشرط قفل الحلقة عند بوابات الانتقال. لا تغيّر أو تستبدل \`workflow-approvals.json\` v3 القديم تلقائيًا. لا حاجة إلى 11 ملف موافقة منفصل بواجهة المستخدم.

## 5. إبطال الاعتمادات وفق التبعيات الفعلية

- تعديل **تعليق المشهد 005**: يبطل موافقة مشهد 005 الحالية، والنسخة التجميعية وMaster وكل مشتقاتها؛ **لا يبطل المشاهد 001–004 لمجرد أن ترتيبها سابق**.
- تعديل تكوين/إضاءة/أصل خاص بمشهد: المشاهد التي تعتمد على ذلك الأصل فقط تُعاد مراجعتها.
- تعديل أصل بصري/صوتي مشترك أو هوية مشتركة: يحسب الخادم المشاهد المتأثرة عبر **رسم تبعيات من ملفات وإصدارات حقيقية**، ويبطل اعتماداتها؛ التغيير الذي يؤثر في كل المشاهد يبطلها جميعًا.
- تعديل النص الأصلي أو إعادة ترتيب القصة/المشاهد: يبطل اعتماد السكريبت/Storyboard وأي مشهد يتغير نصه أو تسلسله أو اعتماده على السياق، وكل ما بعده من تجميع/Master؛ لا يُفترض تعميم الإبطال ولا حصْره دون تحليل التبعيات.
- تغيير بايتات ملف مع إعادتها لاحقًا إلى المحتوى نفسه **لا يحيي** موافقة مُبطلة (hash + epoch + سجل أحداث).
- حارس «لا يبدأ التالي» يوقف **الإنتاج النهائي الجديد** عند أول مشهد غير معتمد، لكنه لا يبطل تلقائيًا صحة المشاهد اللاحقة التي اكتملت قبل تعديل محلي في مشهد سابق؛ يُمنع فقط تجميعها/نشرها حتى إعادة اعتماد الاعتمادات المطلوبة.
- جميع القرارات تفشل بأمان عند فساد السجل أو فقد دليل فعلي أو سباق بين القراءة والكتابة.

## 6. Storyboard PDF = وثيقة إخراج، وليست مشغلًا

الغلاف: القناة والهوية، عنوان الحلقة، عدد المشاهد، المدة التقديرية، رقم إصدار النص الأصلي وStoryboard، البصمتان، التاريخ وحالة «مسودة/معتمدة». الصفحات لكل مشهد توضح:

| قسم | البيانات |
| --- | --- |
| التعريف | رقم المشهد، عنوانه، الهدف والمدة التقديرية |
| النص | الأصل الثابت، مشتق التشكيل، النص الذي سيظهر داخل الكادر |
| الأداء | نبرة/سرعة/وقفات/انفعال الصوت المقترح ومصدر التلاوة إن وجدت |
| الكادر | الشخصيات والخلفية والألوان وتوزيع العناصر |
| الكاميرا | حجم اللقطة، الزاوية، الحركة والـzoom |
| الإضاءة | المصدر والاتجاه والشدة والمزاج |
| الموشن | الحركات والتوقيت التقديري والانتقالات والمؤثرات |
| المخرجات | 16:9 و9:16 وsafe areas مع بيان اختلاف التكوين |
| المرجع | لوحة أو عدة إطارات مرجعية واضحة |
| الإنتاج والمراجعة | تعليمات خاصة ومخاطر وملاحظات وأسئلة مراجعة |

رابط داخلي اختياري من صفحة المشهد إلى شاشة المعاينة في Studio، **وليس افتراض تشغيل AV داخل PDF**. التدقيق العربي يشمل وصل الأحرف والتشكيل واتجاه RTL ومنع القص وفحص كل صفحة بصريًا. لا يعتبر توليد/تصدير PDF اعتماد Storyboard.

## 7. واجهة مراجعة المشهد الواحد

\`المشهد 001 / 012 — مقدمة — نسخة V3 — قيد المراجعة\` ثم **مشغل AV كبير**، شريط زمني وملاحظات مرتبطة بالثانية/العنصر، ملخص موجز: النص والنطق، الصوت والنبرة، حركة الكاميرا والإضاءة، التزامن، النصوص وسلامة 16:9/9:16، الحقوق. زران أساسيان **«طلب تعديل»** و**«اعتماد المشهد»** فقط؛ تفاصيل الجودة وسجلات SHA اختيارية خلف «عرض التفاصيل». بعد اعتماد النسخة الحالية يتحرر المشهد التالي.

- في برنامج مالك واحد لا يلزم **إدخال رمز المالك أو كتابة ملاحظة من 15 حرفًا لكل اعتماد**؛ هذا **يتطلب تعديل مصادقة محميًا على الخادم** (جلسة محلية آمنة قابلة للانتهاء وتجديد الموافقة الصريحة)، ولا يسمح بإزالة الفحص أو كشف الرمز في JavaScript أو localStorage. تأكيد «شاهدت المشهد بالصوت والصورة» مطلوب.
- طلب التعديل يتضمن ملاحظة مفيدة وموضعها. موافقة المشهد لا تزعم تلقائيًا أن المالك شاهد الحلقة كاملة.
- الترجمات/الفلاتر والهوية وتحكم التقدم بين القنوات لا تفقد المسودات غير المحفوظة.

## 8. قرآن كريم وصوت وإذن الاستخدام

- نص الآية يكتبه المالك داخل \`script.md\`، ويُراجع مقابل مصحف معتمد؛ **لا** يستنتج النص من الصوت، ولا يُصحح تلقائيًا أو يستبدل بمحتوى API.
- **لا TTS للقرآن**؛ الصوت القرآني تلاوة بشرية يسلمها المالك أو مصدر بتصريح نشر صالح، مع تعيين المرجع/المصدر والمطابقة وفحص الملف الفعلي.
- إذا لم تُرَد تلاوة لا يختار المحرك تسجيلًا افتراضيًا بصمت.
- صوت الراوي الاعتيادي يمكن توليده وفق إعداد المشهد ثم ضمه إلى الموشن، مع تحقق الحقوق والتزامن. لا يُستخدم مجرد نجاح التوليد كاعتماد.

## 9. الترحيل ووقف التعارضات

1. محرك #77 الحالي v3: \`script → storyboard → voice → motion → av_review → master\`. **لا تغيّر قيمة \`schemaVersion: 3\` ولا تعيد تفسير ملفاتها على أنها سجلات مشاهد V2**؛ أبقها للعرض التاريخي/القراءة الآمنة إلى حين قرار ترحيل مستقل.
2. يبدأ سجل V2 جديد بحالة **غير معتمد** لكل مشهد، بعد جرد حقيقي للمشاهد وأصولها. الوثائق القديمة/الاعتمادات القديمة تظل تاريخية. أي إعادة استخدام مراجعة قديمة تتطلب قرارًا صريحًا مسجلًا يربط الأثر الحالي بعد فحصه؛ **لا موافقة تلقائية**.
3. لا تدمج فروع التطوير المفتوحة في \`main\` لفرض هذا العقد. غيّر **معايير قبول** #71/#73/#74/#76/#77/#79/#80 ثم شغّل التكامل #78 مجددًا.
4. أي مدخل API أو CLI أو Queue أو Render أو Upload يتجاوز حارس V2 يجب أن يفشل بأمان أو يبقى معطلًا؛ تحديث الواجهة فقط لا يكفي.
5. لا تعديل لمقاطع/حلقات الإنتاج عند اختبار الترحيل، ولا حذف لسجلات قديمة أو ملفات /tmp غير مملوكة.

**اختبارات قبول محظورة التجاوز:**
- محاولة رندر المشهد N+1 دون اعتماد N تُرفض، بينما تحضير أصله غير النهائي مسموح.
- طلب اعتماد برمز/جلسة غير مخوّلين، أو بعد انتهاء الجلسة، أو من Origin خارجي، أو ببصمة قديمة، يُرفض.
- نجاح الاختبار/الرندر/الصوت لا يمنح \`approved\` تلقائيًا؛ الاختبار يتحقق من ملف AV حقيقي صوتيًا وبصريًا.
- تغيير صوت مشهد 005 يبطل اعتماده والتجميع/Master، ولا يمحو اعتمادات 001–004؛ تغيير أصل مشترك يبطل كل المستفيدين فقط.
- إعادة نسخة بايتات قديمة لا تعيد اعتمادها؛ اختلاف epoch أو سجل الإبطال يبقي القرار مُلغى.
- قناة أخرى/حلقة أخرى/مسار symlink/طلبا اعتماد متزامنان لا يتداخلان.
- ملف فيديو صامت/مبتور، حقوق تلاوة ناقصة، فحص شرعي غير مغلق، توقيت صوت خاطئ أو Crop/RTL غير صالح تمنع الاعتماد المناسب.
- لا Master قبل مراجعة حلقة كاملة 1×؛ ولا نشر إذا تغيّر بايت واحد بعد اعتماد Master.
- \`npm run check\` + اختبار API محلي موثوق + UI/desktop/mobile + مشاهد AV بشرية، على **SHA تكامل محدد**، قبل وصف V2 بأنه مكتمل.

**معيار الجاهزية:** 726/726 اختبارًا ناجحًا من مرحلة تكامل v1 و10 HTTP checks على Mac **مرجع رجوعي فقط**. لم تختبر بوابات/رحلة V2 الجديدة بعد. لا أي رندر أو نشر أو اعتماد بشري تلقائي.

## 11. خطة تنفيذ في دفعات قابلة للمراجعة

A. عقد أنواع البيانات والأحداث وحراس الانتقال + اختبارات محرك منفصلة دون مدخل إنتاج.
B. اشتقاق بصمات تبعيات المشهد من أصول حقيقية وربط نسخة Storyboard ومصادر النص.
C. دورة رندر AV مشهد/ملاحظات/تصحيح/اعتماد، وربطها بصوت الراوي والتلاوة البشرية.
D. شاشة المشهد المبسطة ومصادقة المالك المحلية الآمنة، بلا توثيق صوري.
E. جمع المشاهد ومراجعة الحلقة 1× ثم اعتماد Master وبوابة نشر الفايل النهائي.
F. تكامل وترحيل/استيراد اختياري صريح في نسخة QA معزولة، وجميع الاختبارات والرصد البصري.
