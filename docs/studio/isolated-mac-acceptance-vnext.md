# قائمة القبول على Mac معزول — Studio vNext

**الحالة:** خطة مراجعة فقط؛ لا يُعد أي بند فيها مُنجزًا قبل وجود سجل تشغيل/لقطات/موافقة فعلية. لا تُجرى هذه الاختبارات على `~/balislam` الإنتاجي أو ملفات حلقاته مباشرة. **لا Vercel ولا نشر ولا دمج**.

## 0. شروط العمل الآمن

1. سجل SHA المرشح من [Draft PR #78](https://github.com/saladin76/balislam/pull/78) قبل البداية، ولا تعتمد على اسم الفرع وحده إذا تقدّم HEAD لاحقًا.
2. استخدم `git worktree` جديدًا في مسار مستقل على القرص يتبع نسخة مرشح التكامل. تحقق أن `git status --porcelain` نظيف في العمل الإنتاجي **قبل** أي اختبار وبعده دون تعديل تلك النسخة.
3. استعمل `BAL_CHANNELS_DIR` و`TMPDIR` يشيران إلى **مجلدات مراجعة مملوكة للوظيفة**؛ انسخ ملفات تكوين القنوات والاختبارات اللازمة فقط، لا مجلدات `episodes` الإنتاجية أو الوسائط الضخمة. اختبارات القراءة المخصصة لملفات PDF الحقيقية يجب أن تتم على **نسخ مراجعة من الأصول** وفي إخراج جديد، لا على الأصل.
4. لا تمرر أي رمز مالك إنتاجي أو مفاتيح نشر/خدمة خارجية، ولا ترفع ملفات إلى Drive، ولا تسجل أي اعتماد فعلي. أي اختبار قبول في الواجهة يستخدم هوية وقيمة سرية اصطناعية وقنوات/حلقات **اختبارية** فقط.
5. إذا كان Mac يواجه ضغط ذاكرة/قرص، أوقف المحاولات المتوازية؛ لا تحاول إصلاحها بحذف ملفات مستخدم أو عمليات أخرى. بوابة التوازي ليست سببًا للمخاطرة بملفات العمل.

## 1. أساس الحزمة والملفات

- `npm ci` داخل worktree المعزول، ثم `npm run typecheck`، ثم `npm test`.
- احفظ العدد الفعلي للاختبارات والتحذيرات، ونسخة Node وnpm ونتيجة `git status --porcelain`.
- تحقق من نجاح GitHub CI وStudio parity على **SHA نفسه**؛ لا تعتمد على فحص فرع قديم.

## 2. P0 — `/tmp` والتوازي

شغّل **تتابعيًا** داخل worktree المعزول:

```bash
node scripts/verify-studio-temp-leaks.mjs
node scripts/verify-studio-temp-leaks.mjs --failure
node scripts/verify-studio-temp-leaks.mjs --cancel
```

وبعد قياس الموارد والموافقة على تحمل Mac للاختبار، شغّل فحص التوازي **مرة واحدة فقط**:

```bash
node scripts/verify-studio-temp-leaks.mjs --parallel
```

هذا السكربت ينشئ TMPDIR خاصًا ويمنع إزالة أي مجلد خارج ملكيته. وثّق نمو المساحة الفعلي داخل مجلده، وعدد مرات التشغيل، ونتائج المحاولة المتزامنة، وموارد Remotion/webpack المؤقتة إن وُجدت. فحص `vm.swapusage` لا يعني تلقائيًا تسربًا.

## 3. P1 — PDF العربي

على ملفات manifest وصور **منسوخة إلى مجلد المراجعة**، استعمل مولد `scripts/studio-storyboard-pdf.mjs` دون أي تغيير في السكريبت أو حالة الاعتماد:

```bash
node scripts/studio-storyboard-pdf.mjs --manifest "/absolute/review/manifest.json" --output "/absolute/review/output-NEW.pdf" --chapter 1
```

كرّر على الفصل الثاني من «دفاتر الزمن» وعينة من «بالإسلام» و«زبدة الكتب» إن توفرت أصولها. استخدم Chrome المتاح للعرض/التصدير، وافحص **كل صفحة بصرية**: اتصال الحروف والتشكيل، RTL، عزل أرقام المعرّفات اللاتينية، غلاف الفصل، النصوص الطويلة وملحقات المشاهد، وعدد اللوحات. لا تدّع اكتمال فحص قناة لا تتوفر لها عينة فعلية.

## 4. القنوات والواجهة

- شغّل Studio على منفذ مراجعة مستقل عن `4321` الإنتاجي، مع `BAL_CHANNELS_DIR` اختبارية؛ لا تُوجّه الخادم إلى مجلدات إنتاج Mac.
- اختبر توافر API القنوات الثلاث، التنقل بين غرفة العمليات وإدارة القنوات ومساحة الحلقة واللوحات والمراجعة المتكاملة والإعدادات.
- شاشات Desktop، هاتف 9:16، عرض أفقي 16:9، تكبير خط المتصفح، RTL، لوحة المفاتيح، فتح الملاحظة في موضع المشهد، والمقاطع المتطابقة للمشهد.
- جرّب `GET /api/episodes/<رقم-اختباري>/workflow` على حلقة اصطناعية **دون اعتماد**؛ لا يجب أن تظهر أي مرحلة `approved` ابتداءً.
- تحقق أن رمز المالك الخاطئ أو المفقود يُرفض، وأن تغيير ملف الصوت أو السكريبت يعيد الحالة إلى مراجعة جديدة. لا يمر اعتماد آية بمصحف غير متاح أو مقارنة غير منجزة.

## 5. البوابات والرندر والاعتمادات

- حالات الفشل المطلوبة: سكريبت بلا اعتماد، Storyboard ناقص، صوت جزئي، MP3 تالف بعد الاعتماد، التوقيت قبل الموافقة الكاملة، صورة/ملف قناة أخرى، فيديو مراجعة صامت، Master ناقص/تغيرت بايتاته، محاولة تسجيل نشر دون `publish` ساري.
- على ملفات **اصطناعية** فقط، اختبر إثبات أن الإلغاء/الفشل أثناء الرندر يترك نسخة الخرج القديمة intact، وأن تشغيل قناتين متوازيتين لا يعزل إلا ملفات كل مهمة.
- لا تُنشئ Master إنتاجيًا ولا تعتبر نتائج الرندر التجريبي إذنًا بالنشر أو اعتمادًا على محتوى الحلقة الحقيقية.

## 6. الإنسان — شرط مستقل لا يستطيع CI إكماله

- صاحب المشروع يراجع السكريبت والآيات والمصادر الشرعية والملاحظات المفتوحة ويعتمدها صراحة.
- يشاهد لوحات Storyboard ويعتمدها، ويستمع إلى كل التعليق الصوتي الفعلي ويعتمده قبل الحركة النهائية.
- يراجع مشاهد الحركة مع الصوت، ثم الحلقة كاملة **بسرعة طبيعية 1×**، والترجمة والآيات وانتقالات الهاتف أفقيًا ورأسيًا.
- يراجع **ملف Master النهائي نفسه** بعد إغلاق الملاحظات، ويوافق على بصمته SHA-256 ثم يسمح بالنشر. لا يجري اعتماد آلي أو نَقْل اعتماد من نسخة قديمة.

## 7. تقرير الإغلاق

أرفق SHA، إصدار Mac/Node، نتائج GitHub والتجارب على Mac ومقاييس TMPDIR، صور وفهرس PDF، نتائج الهاتف، عيوب الواجهة، عدد/أسماء الحلقات الاصطناعية المُستخدمة، وحالة الاعتمادات البشرية. **إن غاب أي بند حاسم فتبقى PR #78 Draft غير قابلة للنشر أو الدمج.** لا تنقل الملفات والاعتمادات التجريبية إلى الإنتاج.
