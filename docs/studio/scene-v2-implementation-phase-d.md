# Studio V2 — الدفعة D1: ترتيب المشاهد من خطة الحلقة الحقيقية

**الحالة:** تنفيذ جديد في PR #77، **لم يُختبر بعد على Mac**. مرجع نجاح Phase C هو فقط commit `b7fa56a` مع **92/92 files و719/719 tests**، ولا تُنسب تلك النتيجة للتعديلات الجديدة.

## ما أُنجز

- `src/workflow/scenePlanV2.ts`: قارئ خادم فقط لملف `plan.json` الحقيقي بعد تحديد القناة والحلقة وتحقق ملكية الملف. يُخرج الترتيب الأصلي للمشاهد عبر جميع الفصول، ويمنع التكرار، والعبور بين القنوات، وخطأ الفصل، والملف التالف أو الرابط الرمزي.
- يميّز بين المشهد **البصري الصامت** (قد يكون صوت البيئة فقط، بلا راوي)، والمشهد الذي يحتوي تعليقًا منطوقًا، والمشهد الذي يحتوي مرجع آية وتستلزم تلاوة بشرية يرفعها المالك. **لا يوجد Quran TTS ولا اعتماد منفصل للصوت.**
- `tests/workflow-scene-plan-v2.test.ts` تحتوي **9 اختبارات مكتوبة ولم تُشغّل بعد** تشمل `c1-s0` و`c2-v1`، ترتيب المشاهد، الهوية والملفات غير الآمنة.
- أمثلة حقيقية تم فحص بياناتها من مستودع GitHub: حلقة دفاتر الزمن `001-adam-beginning` تحتوي 80 مشهدًا بما فيها مقدمات صامتة ومشاهد آيات، وحلقة بالإسلام `001-know-the-truth` تحتوي 114 مشهدًا. لم تُعدّل أي من هاتين الحلقتين.

## ما **لم** ينتهِ بعد

- قارئ الخطة لا يربط نفسه بواجهة HTTP أو Render CLI أو طابور المهام. يجب أن يُستخدم عبر محول خادم موثوق تحت **نفس قفل الكتابة** المستعمل في الإنتاج وتحرير الملفات.
- `sceneArtifactsV2.ts` في الدفعة B لا تزال تشترط ملف `narration` فعلي لكل مشهد، وهو غير مناسب للمشاهد البصرية الصامتة؛ لا تتجاوز القاعدة بواسطة ملفات MP3 وهمية أو قبول فيديو صامت لمجرد وجود امتداد `.mp4`. يجب تصميم سياسة موجّهة صراحة للمشهد الصامت والتحقق من مكونات الصوت والوسائط الفعلية قبل تفعيل الإنتاج.
- مصدر الترتيب الحالي `plan.json` قد يتغير بعد اعتماد Storyboard، ولذلك يجب ربط ترتيب المحتوى بإصدار `script` وStoryboard المعتمدين، وإبطال الاعتماد عند تغيير النص/المشهد والتبعيات.
- لا توجد حتى الآن آلية مثبتة بمشاهدة فعلية لصوت وفيديو المشهد، ولا جلسة مالك إنتاجية، ولا اعتماد Master أو تشغيل نشر من V2.
