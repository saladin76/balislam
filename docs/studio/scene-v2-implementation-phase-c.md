# Studio V2 — مرحلة C: خدمة قرارات المشهد على الخادم

**الحالة:** كود على فرع PR #77 لم تُشغّل اختباراته بعد. **غير موصول بالواجهة أو الرندر أو النشر**، ولا يجوز اعتباره صلاحية لإنتاج محتوى. معيار الإصدار لا يزال [Studio scene-first V2](https://github.com/saladin76/balislam/blob/work/studio-integration-validation-20261107/docs/studio/scene-first-production-v2.md).

## العمل المُنفّذ

- \`src/workflow/sceneServiceV2.ts\` خدمة **server-only** تجمع \`sceneV2.ts\` و\`sceneStoreV2.ts\` و\`sceneArtifactsV2.ts\`، ولا تنشئ أي HTTP endpoint.
- جلسة المالك تؤخذ من \`authenticate()\` الموثوق، لا من JSON المتصفح. \`command()\` يقبل حقولًا محددة فقط: \`action,sceneId,expectedFingerprint,note,second,elementId\`. يحظر تمرير دور أو بصمة الفيديو أو مسارات الملفات أو الموافقة من العميل.
- \`sceneOrder()\` و\`currentSceneManifest()\` يقدمهما خادم Studio من الملفات الموثوقة للسيناريو؛ الطلب لا يختار قناة/حلقة/مسار. يحمي \`withArtifactLock\` جلب البيانات والتحقق والاعتماد ويجب أن يكون **نفس القفل المُستخدم للكتابة الحقيقية** في الرندر والسكريبت والصوت.
- \`begin\`: بعد التحقق الفعلي من اعتماد السكريبت الأصلي والـStoryboard عبر \`assertLockedScriptAndStoryboard()\`، لا يبدأ الإنتاج النهائي للمشهد التالي قبل اعتماد كل ما يسبقه.
- \`inspect\`: يفحص من جديد الملفات الحقيقية لكل مشهد معتمد أو قيد المراجعة، ويلغي الاعتماد الذي تغيرت تبعياته. لا يعرض في الرد ملفات المسارات أو مفاتيح التوقيع أو بيانات الحقوق الحساسة.
- \`submit\`: يحسب بصمة فيديو المشهد الحالي وصوته وأصوله ويقبل الطلب فقط إذا تطابق الإصدار المعروض في الواجهة.
- \`approve\`: بعد تقديم المشهد للمراجعة، يستدعي \`verifyCurrentSceneAvReview()\` المستقل الذي **يجب** أن يثبت تشغيل ملف صوتي مرئي حقيقي ومشاهدة المالك له وحقوق التلاوات/الأصول. يعيد حساب البصمات بعد التحقق المتزامن قبل كتابة قرار المالك في السجل الموقّع. **لم يُنفّذ متحقق المشاهدة الحقيقي بعد**؛ في اختبارات الوحدة فقط تستعمل محاكاة معطيات.
- \`request_changes\`: يسجل ملاحظة مرتبطة بثانية أو عنصر ويُبطل موافقة المشهد دون إبطال باقي المشاهد غير المتأثرة.
- \`assemblyEligibility\`: بصمة وشروط أهلية التجميع من كل المشاهد الحالية المعتمدة، **ليست** رندرًا ولا اعتمادًا للحلقة أو Master ولا نشرًا.
- أصلح \`reconcileSceneInputs\` سلوك إدخال ملف الفيديو لأول مرة أثناء \`producing\`: لا يُعيد الحالة صامتًا إلى \`draft\`.

## اختبار V2 المطلوب

أضفنا \`tests/workflow-scene-service-v2.test.ts\` (11 اختبارًا) لعزل قرارات المتصفح وتحقق المالك وعدم السماح بتجاوز السكريبت/Storyboard، وقفل المشهد التالي، وتغيير MP3 أو MP4، وتصحيح الثانية، وإبطال المشهد المحلي، وإعادة اختبار البايتات بعد الدليل، وتزامن اعتمادين. **الملفات الصوتية والفيديو في الاختبارات بايتات اصطناعية**؛ نجاح الاختبارات لا يثبت جودة فيديو فعلي أو مراجعة صوتية مرئية بشرية.

## ما بقي قبل وصل الواجهة أو الرندر

1. **ملفات منشأ حقيقية:** \`plan.json\` وتحديد مشاهد القناة/الحلقة وتوقيتها، ملفات \`script.md\` المرجعية وملفات مشتقات التشكيل والنبرة وStoryboard ومراجعات الحقوق، وصوت وفيديو لكل مشهد.
2. **حماية مشتركة فعلية:** دمج نفس القفل في كل مسار تعديل من API وCLI وQueue والرندر والنشر، مع تجميد الملف خلال التحقق/النسخ؛ لا تفويض اعتماد قبل حل السباق مع الكتّاب.
3. **متحقق AV مستقل:** التأكد من وجود فيديو playable بصوت وصورة (باستخدام فحص الوسائط الحقيقي)، وتطابق النطق والحقوق، وسجل مراجعة المالك للمشهد نفسه؛ لا إثبات بمجرد \`confirmWatched=true\` أو رمز عميل.
4. **جلسة مالك محلية:** إعداد دخول واحد آمن بدل كتابة رمز لكل مشهد، مع Origin/CSRF/session expiry والتحديث الآمن.
5. **واجهة المشهد والرندر:** ربط فيديو/صوت المشهد، ملاحظات زمنية، طلب تعديل، اعتماد، ثم إنتاج التالي. بعد ذلك تجميع ومراجعة الحلقة 1× وMaster النهائي والنشر الآمن.
