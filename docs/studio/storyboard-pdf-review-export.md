# Studio — تصدير Storyboard PDF للمراجعة فقط

قرار 6 نوفمبر 2026: حل مشاكل الطباعة العربية وحجم الصور والمقارنة بين 16:9 و9:16 دون تعديل محرك الرسم أو إعادة إنتاج V7 أو الكتابة على أي نسخة معتمدة.

## نطاق الأداة

الملف `scripts/studio-storyboard-pdf.mjs` أداة CLI مستقلة، تستخدم Node.js القياسي. **تقرأ فقط** ملفات JSON وPNG/JPG/WebP المحفوظة بالفعل؛ لا تنشئ صور المشاهد، ولا تغير الخطة أو السكريبت أو موافقات Storyboard، ولا تستخدم أي مفتاح صوت ولا ترفع إلى Drive. المخرجات مراجعات `PENDING_REVIEW` دائمًا.

يدعم:
- `tech-reviews/020/docs/storyboard-001-v1.1.json` في «دفاتر الزمن» بمراجع صور `strips/…` الواقعة في المجلد الأعلى من `docs`.
- `storyboard-visual/v021/manifest.json` في «زبدة الكتب» مع `files[].path` وصور المشاهد.
- أي ملف موحد يحتوي `scenes: [{id, image, portraitImage?, chapter?, chapterTitle?, narration?, notes?}]` لقناة «بالإسلام» أو غيرها، دون فرض هوية بصرية جديدة.

الـPDF لكل مشهد صفحة A4 أفقية مستقلة: صورة كبيرة غير مقصوصة، النص العربي باتجاه RTL والتشكيل كما في المصدر، مُعرّفات المشاهد `<bdi dir=ltr>`، اسم القناة، الفصل، نوع المشهد، حالة المراجعة والإصدار، والتعليقات. إن وُجدت صورة عمودية، تظهر بجانب الأفقية للمقارنة؛ وإن لم توجد لا تُختلق صورة عمودية. النص الطويل يُنقل **كاملًا** إلى صفحة ملحق بدل إخفائه.

## إصدار معاينة الفصل الأول دون تغيير الحلقات

على Mac بعد فحص النسخة البرمجية في worktree مستقل:

```bash
mkdir -p "$HOME/Balislam-Preview-Sync/storyboard-review"
node scripts/studio-storyboard-pdf.mjs \
  --manifest "$HOME/balislam-storyboard-visual-preview/channels/dafatir-alzaman/episodes/001-adam-beginning/tech-reviews/020/docs/storyboard-001-v1.1.json" \
  --chapter 1 \
  --output "$HOME/Balislam-Preview-Sync/storyboard-review/dafatir-001-v1.2-chapter1-PREVIEW.pdf"
```

إذا لم يكن Chrome متاحًا، يخرج البرنامج بالرفض مع HTML قابل للطباعة بالمتصفح، ولا ينشئ ملف PDF زائفًا. يمكن تمرير `--chrome "/absolute/path/to/Google Chrome"`. الخيار `--html-only` ينتج HTML فقط دون محاولة تشغيل Chrome. لا تُعد تشغيل الأمر بالاسم نفسه: كل اسم إصدار موجود يُرفض حفاظًا على النسخ. هذه الأداة لا تحذف ملفات التجربة.

## إصلاح macOS بعد فحص صاحب المشروع (7 نوفمبر 2026)

أثبت تشغيل صاحب المشروع على `cbc880c` أن **TypeScript ناجح**، وأن اختبارات PDF الستة الجديدة ناجحة، وأن العدد الكلي **585 ناجحًا من 586**. الفشل الوحيد في الاختبار السابق غير المرتبط بالطباعة `tests/render-pool.test.ts:287`: استعادة العملية اليتيمة تعتمد على `/proc` غير الموجود في macOS. في commit `929659b` نُقل التصحيح المجرّب سابقًا على Mac من PR #61: استعلام `/bin/ps -p PID -o lstart=` مع المقارنة ببصمة بداية العملية قبل إيقافها لحماية PID المعاد استخدامه؛ تُرك Linux كما كان. لم تُعطل أي اختبارات.

**لا يستند اجتياز فحص Mac إلى الفرع الجديد حتى يظهر `CHECK_OK` عند أو بعد commit `929659b`.** اختبارات PDF الستة تعني توافق الـJSON ومحددات HTML ونسخ الحفظ، وليس تحققًا من شكل PDF الحقيقي في Chrome. بعد الفحص البرمجي يلزم توليد نسخة فعلية للفصل الأول وفحصها بصريًا دون إعادة إنتاج أي فيديو.

### حدود الاعتماد

1. إصلاح التخطيط لا يكبر الكتابة **الموجودة داخل صورة Storyboard نفسها** إلا بقدر زيادة عرض الصورة؛ إن احتاج صاحب المشروع قراءة بيانات دقيقة جدًا، يستخدم ملفات الـStoryboard الأصلية ويكبّرها ولا يعدّل محرك الرسم.
2. الصور التسع مصدرها **Contact strips أفقية**. لا تُنتج الأداة مقارنة 9:16 وهمية؛ المقارنة الجانبية تعمل فقط إذا كان `portraitImage` موجودًا فعليًا.
3. لا موافقة تلقائية على Storyboard، ولا مساس بـV7/السكريبت/الآيات/الصوت، ولا استبدال لـPDF V1/V1.1 على Drive. هذه مراجعة جودة **لمولّد PDF** فقط.
4. CI GitHub البعيد ما زال أحمر في هذا الفرع؛ نجاح Mac السابق يعود إلى `552d7f8` ولا يشمل تحسينات التخطيط الجديدة.

## اختبارات التسليم المطلوبة

- `npm run gate` (TypeScript + جميع Vitest) على Mac بفرع التغيير الحالي، دون تجاوز الاختبارات.
- `tests/studio-storyboard-pdf.test.ts`: التشكيل، اتجاه العربي والرموز، مقارنة الأحجام، استكمال النص في الملحق، غياب الاعتماد التلقائي، منع `../` وsymlink، عدم استبدال إصدار موجود، توافق البيانين الحقيقيين.
- **مراجعة بصرية لازمة:** افتح أول صفحات PDF المطبوعة من Chrome على Mac (الفصل 1) عند 100%، ثم افحص عدد الصفحات/صورة كل مشهد، عدم تقسيم الصورة على صفحتين، عدم قطع الحروف أو الحركات، وقراءة بيانات كل صفحة؛ اختبر ظهور عمودي إذا كان متاحًا. نتائج Vitest وحدها ليست اعتمادًا بصريًا.
- اختُبر نموذج صناعي **غير إنتاجي** محليًا بمخرج PDF عبر محرك طباعة مستقل: صفحتان لمشهدين، مع RTL والتشكيل، وصورتين مقارنتين في الأولى. لا يثبت ذلك تطابق Chrome على Mac ولا صحة المحتوى الشرعي؛ الاعتماد البصري الحقيقي **معلق**.
- لا تعيد رفع V1/V1.1 إلى Drive ولا تضع النسخة التجريبية مكانهما. إن اعتمد المراجع إصدارًا لاحقًا، يُرفع باسم جديد وتتحقق MD5/sha256 والرابط كملف مستقل. لا تشغيل ناقل تلقائي.
