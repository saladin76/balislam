# إعادة هيكلة استوديو القنوات الثلاث — UX/UI V2

الحالة: **مرحلة أولى قيد الاختبار**؛ لا يعني هذا المستند اكتمال إعادة التصميم.

## المشكلة المرصودة
تجمع واجهة الإنتاج اليوم عشرات الأوامر في الشاشة نفسها. يظهر الصوت والتلاوة والمكتبة دون فصل واضح بين المعاينة والإنتاج، وتسهل الخلط بين توليد التعليق وجلب الآية. كذلك توجد ملاحظات تقنية كثيرة دون ترتيب بحسب تأثيرها على قرار الإنتاج. هذه المشكلات مثبتة بتدقيق `docs/STUDIO_UX_COMPREHENSIVE_AUDIT_2026-11-04.md` وصورة شاشة «صوت الحلقة» التي راجعناها.

## البنية المستهدفة

**مستوى 1 — نظرة اليوم:** هوية القناة، الحلقة النشطة، حالة العمل، وآخر إجراء يحتاج اتخاذ قرار. لا تعرض غرفة العمليات وكل الحلقات في الوقت نفسه.

**مستوى 2 — إنتاج حلقة واحدة:** خط إنتاج من ست محطات: البحث ← السكريبت ← الستوري بورد ← الصوت ← المشاهد ← النشر. تظهر في كل مرحلة الأدوات الخاصة بها فقط، مع حفظ واضح وعلامة تقدم وأخطاء قابلة للفتح.

**مستوى 3 — المواد والإعدادات:** المكتبة، الهوية، القناة، التوصيلات، وأذونات المحتوى تحت «إدارة الاستوديو»، لا كأزرار رئيسية منافسة للعمل اليومي.

## تصميم مرحلة الصوت

- لوحة موجزة: عدد مقاطع الراوي المكتملة، والمفقودة، ومهام الصوت.
- المسار 01 — التعليق الصوتي: التشكيل، إعدادات الراوي، حساب التكلفة، توليد الناقص، حالة كل مقطع. لا نُخفي تنبيهات عدم الحفظ.
- المسار 02 — تلاوة القرآن: البحث عن قارئ، مقارنة صوتية حرة، ثم اعتماد مصدر إنتاجي **منفصل تمامًا** عن المعاينة.
- اعتماد AlQuran Cloud للإنتاج مشروط بوجود حق نشر موثق لتسجيل القارئ؛ يجب إظهار صاحب الحقوق ورابط الإذن ونطاقه وتاريخ تأكيده. خدمة API ليست تصريحًا بنقل التسجيل للنشر.
- بعد الاعتماد: جلب تلاوة كل آية، التحقق من القارئ/رقم الآية، قياس المدة، وتعبئة وسائط بطاقة الآية والرندر بنفس آلية Quran Foundation.
- القارئ المختار هنا هو **افتراضي للقناة**؛ دعم تجاوز القارئ *للحلقة* سيكون مرحلة منفصلة حتى لا نضيف تخزينًا جديدًا قد يتعارض مع بيانات الحلقات الحالية.
- عند فشل الاستيراد: استعادة إعداد المصدر السابق؛ لا تبديل صامت لصوت مختلف ولا حذف لملفات الحلقة الأخرى.

## مراحل إعادة التصميم القادمة

1. **الهيكل الرئيسي والتنقل:** شريط واضح يعرض القناة/الحلقة، وحدة حالة واحدة للمشكلات الفعلية، بحث سريع عن الحلقة، وعدم ازدحام الإدارة في الرأس.
2. **المشاهد والمعاينة:** محرر المشهد يسار/يمين وفق RTL؛ معاينة كبيرة منفصلة عن خصائص النص؛ إعدادات متقدمة مطوية؛ مؤشرات منطقة الأمان 16:9 و9:16.
3. **الصوت والتزامن:** مجموعات واضحة للراوي، التلاوة، المقاطع؛ قائمة اختيار قارئ لكل حلقة؛ شارة «صالح للنشر» مبنية على حقوق فعلية وليس اختيارًا بصريًا.
4. **غرفة العمليات:** مشاريع القنوات الثلاث تظهر في قائمة قابلة للتصفية مع حالة الإنجاز وأولوية التحرير، وليس لوحة مزدحمة.
5. **نظام تصميم:** شبكة 8px، تسلسل خطوط عربي واضح، تباين WCAG AA، لوحة ألوان متوافقة مع هوية كل قناة، أزرار رئيسية/ثانوية ثابتة، حالات تحميل/خطأ/فارغ متسقة، ودعم لوحة المفاتيح.
6. **اختبارات الجودة:** فحوص RTL، قارئ الشاشة، 360/768/1440px، عدم قص المحتوى، التنقل من دون فقد التعديلات، السيناريو الكامل لحلقة من كل قناة.

## ضوابط حماية العمل
- لا تغيير أو استبدال صامت في `plan.json` أو `script.md` أو الصوت المعتمد.
- لا يُعتبر بدء Vite اختبارًا بصريًا؛ يجب فحص رحلة مستخدم فعلية.
- لا تفعيل تلقائي لتسجيل متاح للمعاينة دون حق نشر ملائم، ولا تخزين لمفاتيح أو روابط خاصة سرية في مستودع Git.
- لا دمج للدفعات اللاحقة في `main` قبل TypeScript وVitest ومعاينة المتصفح.
