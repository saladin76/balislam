## فحص Mac للمرشح الموحّد — يُشغل كما هو قبل أي دمج

```bash
cd "$HOME/balislam"

# افحص حالة الإنتاج دون تعديلها
git status --short
git branch --show-current
git worktree list

# الفرع المجمّع فقط، والمجلد معزول عن ملفات الإنتاج
git fetch origin integration/studio-20261107-release-candidate

BAL_STUDIO_TEST_BRANCH=integration/studio-20261107-release-candidate \
BAL_STUDIO_TEST_DIR="$HOME/balislam-studio-release-candidate-20261107" \
BAL_STUDIO_TEST_PORT=4323 \
bash <(git show origin/integration/studio-20261107-release-candidate:scripts/studio-terminal-branch-check.sh) check
```

شرط القبول: `TEST_HEAD` يطابق SHA الحالي لفرع التكامل، و`CHECK_OK`، TypeScript وجميع اختبارات Vitest ناجحة. تجنب تشغيل `fresh-start.command` أو `reset --hard` أو محاولة إصلاح test عبر حذف العمل غير المتعقب. إذا وجد مجلد اختبار مستخدم وعليه تعديلات، استعمل مسارًا **جديدًا** بدل الكتابة فوقه.

بعد نجاح check، اختياريًا شغّل `serve` بالأمر نفسه لاختبار واجهة **المراجعة فقط** على `127.0.0.1:4323`؛ لا تولد صوتًا مدفوعًا ولا ترندر مقطعًا كاملاً دون قرار الحلقة. جرّب أن وجود ملف صوت غير معتمد لا يتيح Master، وأن تغييره يبطل الموافقة؛ لا تختبر على النسخ الإنتاجية المعتمدة.

## ترقية Mac للإنتاج — لم تنفذ

بعد نجاح GitHub CI + فحص Mac وعرض فرق الملفات وموافقة المالك، تُدمج النسخة إلى `main` ببصمة SHA نهائية. **لا تُحدّث `~/balislam` آليًا**: قد يكون فرع مراجعة يحوي تعديلات محلية ووسائط غير متتبعة. احصر التحديث في إجراء يدوي يحافظ على البيانات، وحدد checkout المستخدم فعليًا لخادم `localhost:4321`. لا تفتح 4321 من worktree الاختبار عن طريق تغيير منفذ المعاينة.
