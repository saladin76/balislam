# Studio V2 — الدفعة B: بصمات المشهد من الملفات الحقيقية

**الحالة:** تنفيذ تجريبي في PR #77. **لم يُجرَ فحص Mac بعد إضافة هذه الدفعة**. لا يُفعّل API/CLI/renders/publishing حاليًا بناءً عليه.

## ما أُضيف

- \`src/workflow/sceneArtifactsV2.ts\`: قراءة manifest مُعرّف من **الخادم وحده** لمشهد واحد، يضم النص المرجعي، التشكيل، النبرة، Storyboard، الأصول، تسجيل الصوت/التلاوة، التزامن، فيديو المشهد المركّب، الحقوق والأصول المشتركة المستخدمة فيه فعلاً.
- قراءة ملفات فعلية وحساب \`SHA-256\` و\`epoch\` من معلومات الملف؛ يقرأ فيديو المشهد **ببايتاته الحقيقية** في حقل \`inputs.video.sha256\` (لا من حجم/اسم الملف). يعتمد على حارس \`resolveArtifact()\` الحالي لمنع الخروج من الحلقة والروابط الرمزية/الصلبة.
- \`SceneFileManifestV2\` يحدد الإصدار والملفات لكل نوع داخل الخادم. لا يقبل أصناف ناقصة أو إضافية، ويشترط إدراج \`script.md\` ضمن النص المرجعي، وملف صوتي ضمن المواد الصوتية، وملف MP4 وحيد داخل الحلقة لمراجعة الفيديو.
- \`shared\` يضم **التبعيات المشتركة المستخدمة في هذا المشهد** فقط، كي لا يعيد اعتماد مشاهد غير متأثرة بتغيير أصل آخر. تجزئاتها مربوطة بالقناة/الحلقة/رقم المشهد.
- يرفض الملفات المفقودة، المسارات الملتوية، التكرار، وسجلات الاعتماد باعتبارها أدلة صورية عن نفسها.
- \`tests/workflow-scene-artifacts-v2.test.ts\`: **11 اختبارًا جديدًا مكتوبًا، غير مُشغّل بعد** على Mac؛ ملفات مؤقتة حقيقية لا تمس الإنتاج، لا رندر/تلاوة/رفع.

## الحدود الدقيقة

هذه الوحدة **تثبت تطابق البايتات، ولا تثبت أن الفيديو قابل للمشاهدة أو يحمل صوتًا صحيحًا**. ملفات MP4 في اختبارات الوحدة مجرد بايتات اختبار. لا تُحوّل البصمة إلى \`approved\` تلقائيًا.

وجود \`withArtifactLock\` مطلوب، لكن **التأكد من أنه نفس قفل جميع كُتّاب السكريبت/الصوت/الفيديو لم يُربط بعد**. يجب أن يبني خادم Studio manifest من سياق قناة/حلقة/مشهد موثوق لا من جسم طلب HTTP؛ ويجب استخدام هذه الوحدة *تحت القفل المشترك* عند كل اعتماد وإنتاج ونشر. لا يكفي إرفاق رد الاتصال الشكلي في الاختبار لتأمين التطبيق.

للمرحلة التالية لا بد من:
1. توليد manifest رسمي من \`plan.json\` وبنية ملفات المشهد الفعلية وملفات الحقوق/التشكيل، مع تحديد مسارات الفيديو المركب المؤقتة قبل تحويلها إلى ملف AV معتمد.
2. حارس جلسة مالك محلي لا يطلب رمزًا مع كل مشهد، ومراجعة تشغيل فعلي لمقطع AV بمساري صوت وصورة وملاحظات صريحة؛ لا يتلقى الخادم \`approved=true\` من المتصفح كدليل.
3. ربط V2 بمسارات API وCLI وQueue والرندر تحت قفل مشترك، ثم تجميع المعتمد فقط ومراجعة الحلقة 1× واعتماد Master ببصمته ونشر الملف نفسه.
4. فحص TypeScript، اختبارات V2، الاختبارات الكاملة، ثم اختبارات API وMac المرئية وAV الحقيقية قبل وصف النظام بأنه متكامل.

**المرجع الموثق السابق:** نجاح الدفعة A عند SHA \`c0913bb\`: TypeScript، 20/20 اختبار V2، 697/697 اختبار إجمالي على 90 ملفًا، Mac QA مستقل. **لا تُنسب هذه النتيجة إلى كود الدفعة B اللاحق**.
