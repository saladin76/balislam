# خريطة الاستوديو وسجل التحديثات

> **لمن هذه الوثيقة:** لكل محادثة ووكيل ومطوّر يعمل على أي قناة. تُقرأ **قبل أي عمل** بعد سحب `main`، ومعها رسالة تكليف القناة (`docs/<القناة>/briefing.md`).
> **حالتها:** مطابقة لـ `main` حتى ١٢ نوفمبر ٢٠٢٦ (D106). تُحدَّث في commit كل قرار يغيّر شاشة أو بوابة أو سلوكًا ظاهرًا للمالك، فلا تبقى نسختان مختلفتان.
> **الأسبقية:** `CLAUDE.md` فوقها، ثم سياسات القنوات `docs/studio/channel-production-policies.md`، ثم مرجع كل قناة. هذه الخريطة تصف ما هو مبني فعلًا، ولا تنشئ قاعدة جديدة.

> **مرحلة الاستقرار وتجميد الميزات (D106، ١٢ نوفمبر):** أمر عمل من صاحب المشروع (`docs/studio/stabilization-brief.md`). لا ميزات جديدة ولا تغيير في سلوك ظاهر للمالك إلا إصلاح خطأ أو ما يطلبه التكليف؛ أي طلب ميزة يُسجَّل في `docs/studio/backlog.md` ولا يُنفَّذ إلا بقول المالك «نفّذه الآن رغم التجميد». الأخطاء المعروفة في `docs/studio/known-issues.md` مرتبة بالشدة، ومنها يبدأ كل إصلاح (اختبار يعيد إنتاج الخطأ أولًا). المرحلة تنتهي بقرار المالك وحده.

## أ. نظرة عامة

### استوديو واحد للقنوات الثلاث
- يعمل على جهاز المالك وحده: `cd ~/balislam && npm run app` ← `scripts/studio.mjs`، على **`http://127.0.0.1:4321`**.
- **نسخة واحدة دائمًا:** إن كان المنفذ 4321 مشغولًا باستوديو من المجلد نفسه، يغلقه التشغيل الجديد بلطف ويأخذ مكانه (ويغلق بقايا 4322–4329). وإن كان مشغولًا ببرنامج آخر يقول ذلك بالعربية ويتوقف. لا انتقال صامت إلى 4322 (`strictPort` في `app/vite.config.ts`، و`scripts/studioInstance.mjs`).
- **سياق المالك (بلا كلمة مرور):** كل طلب من الصفحة نفسها على 127.0.0.1 هو المالك. الطلب من عنوان أو موقع آخر يُرفض 403. السجل موقَّع بمفتاح الجهاز (`assertSceneOwner` في `src/studio/sceneService.ts`، و`src/studio/ownerContext.ts`).
- **القنوات:** «بالإسلام» (`balislam`)، و«دفاتر الزمن» (`dafatir-alzaman`)، و«زبدة الكتب» (`zubdat-alkutub`). لكل قناة مكتبتها وهويتها وقواعدها، ولا يعرض الاستوديو لقناة إلا ما يخصها.

## ج. البوابات والقواعد الثابتة

**سلسلة الاعتماد** (السلطة الوحيدة: سجل «إنتاج المشاهد»، `src/studio/sceneProduction.ts` و`sceneService.ts`):
اعتماد السكريبت ← اعتماد الستوري بورد (معًا بزر «اعتمد التجهيز»، مرة واحدة، D76) ← كل مشهد بالصوت والصورة بالترتيب ← اعتماد التجميع (١× وكل وصلة) ← اعتماد Master (الملف نفسه) ← إذن النشر.

- **D35:** لا تجميع ولا Master ولا نشر وفيها مشهد «مشروط بالتلاوة» أو آية بلا تلاوة معتمدة. لا ينطبق على آيات «زبدة الكتب» الصامتة (D68)، ويبقى للبسملة.
- **لا يحدث أبدًا:**
  - توليد صوت مدفوع أو نشر دون إذن صريح من المالك في كل مرة؛
  - إرسال قرآن أو بسملة إلى توليد الصوت، ولو نصًا مجاورًا (`assertNoQuranForTts`)؛
  - اعتماد نيابةً عن المالك، أو نقل اعتمادات آليًا؛
  - حذف تسجيل مدفوع (`takes` و`voice/superseded/`)؛
  - أوامر `git` أو `stash` أو `pull` أو `npm install` تُعطى للمالك: الاستوديو يتولاها، ويكفيه `cd ~/balislam && npm run app`؛
  - دفع من الاستوديو، **إلا** الحفظ الآلي لمحتوى المالك إلى `main` عبر البوابة (D101)، وصندوق الملاحظات إلى `studio-notes`؛
  - أثر للذكاء الاصطناعي أو لأسماء الأدوات في أي شيء يُنشر (`src/package/traces.ts`).

## و. للمطورين والوكلاء

**قبل أي عمل:**
1. اسحب آخر `main`، واستعمل `git ls-remote origin refs/heads/main`، فالمراجع المحلية قد تتأخر. محتوى المالك يصل إلى main باستمرار (D101).
2. اقرأ `CLAUDE.md`، ثم رسالة تكليف قناتك `docs/<القناة>/briefing.md`، ثم هذه الخريطة.
3. شغّل `npx bal notes --open` وعالج ملاحظات المالك المفتوحة. بعد الإصلاح شغّل `npx bal notes resolve <id> --answer "…"`، واحفظ `notes/resolved.json` مع الإصلاح نفسه.

**كيف تختبر:**
- استعمل worktree خاصًا من `origin/main` (`/tmp/<اسم>`) ومنفذًا خاصًا (4401 وما بعده)، ولا `git stash` أبدًا. تحقق من مساحة القرص بـ `df` أولًا.
- شغّل الاستوديو بـ `npx vite --config app/vite.config.ts --port <المنفذ> --strictPort --host 127.0.0.1`، ثم Playwright (`require('playwright')` مثبّت).
- اجعل مفتاح الصوت فارغًا، واعترض أي طلب ElevenLabs. ولا تكتب الاعتمادات أو السجل في commit.
- شغّل `app/scripts/ui-audit.mjs` و`app/scripts/scroll-qa.mjs`، على ١٤٤٠ و٣٩٠، فاتحًا وداكنًا.
- لأي تغيير في تشغيل «الجمل» أو المعاينة: `node app/scripts/sentence-replay-qa.mjs` (استوديو خاص على نسخة من حلقة، وصوت مزيّف داخل العملية، بلا طلب خارجي؛ D105).
- ادفع إلى `main` عبر بوابة الرفع الإلزامية بلا تجاوز. إن انتهت المهلات بسبب حمل الجهاز، أعد المحاولة؛ `BAL_STUDIO_AUDIT_VITEST_WORKERS=1` يغيّر الجدولة فقط.
- الاختبارات لا تثبّت قيمًا يحرّرها المالك في الاستوديو (نص مشهد، نبرة، سلسلة) إلا في نسخة محفوظة (`versions/` أو fixtures).

**رقم القرار:** شغّل `node scripts/decisions.mjs next` **قبل الكتابة مباشرة**، بعد السحب، فقد تصادمت الأرقام مرارًا. عرّف القرار المشترك في `docs/balislam/06-decisions.md`، وضع في السجلين الآخرين إحالة بصيغة «(Dنن، التعريف: docs/balislam/06-decisions.md)». ثم تحقق بـ `node scripts/decisions.mjs check`.

**التقرير للمالك:** بالعربية وبكلام بسيط، ويتضمن:
- ما تغيّر؛
- الـcommit في main ورقم القرار؛
- ما ينتظر قراره، مع التوصية؛
- وما يفعله على جهازه، وأقصاه `cd ~/balislam && npm run app`. لا أوامر git.
