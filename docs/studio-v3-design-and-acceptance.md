# Studio V3 — هندسة التصميم والتسليم والإنتاج

> الحالة: تنفيذ تجريبي على فرع `fix/studio-preview-safe-cloud-sync` فقط. لا يُعد أي عنصر معتمدًا للنشر قبل اختبار Mac وموافقة صاحب القنوات.

## 1. هيكلة التنقل

- **الحلقات**: قوائم كل قناة منفصلة، بحث وتحديد وفتح الحلقة، إنشاء حلقة.
- **غرفة العمليات**: جدول نشر جميع القنوات، خط الإنتاج، بنك الأفكار والتنبيهات؛ تحت قسم مستقل بعيد عن تحرير الحلقات.
- **مركز التسليمات**: حالات النقل من GitHub إلى Mac، الملفات التي تحقق النظام من وصولها إلى Drive، روابطها، فلاتر القنوات، ونسخ تقرير مراجعة.
- **مساحة الحلقة**: البحث، السكريبت، Storyboard، الصوت، محرر المشاهد، حزمة النشر.
- **مكتبة الأصول والمختبرات والمراجعات الفنية**: أدوات مستقلة عن سياق الحلقة.
- **إدارة القناة والهوية والاتصالات**: بعيدة عن شاشة المراجعة.

## 2. لوحة القيادة

غرفة العمليات الموجودة بالفعل هي المصدر المعتمد للجدول والأفكار ومراحل الحلقات، وليست هناك حاجة إلى مصدر بيانات مكرر. جرى فصل رابطها عن «الحلقات»، وإضافة مركز التسليمات كنقطة متابعة مستقلة. لا يعرض المركز حالة «معتمد» مستنتجة من رفع ملف؛ الرفع فقط دليل وصول.

## 3. مراجعة Storyboard والفيديو

- عرض موسع للصور/بطاقات المشاهد مع ترك مساحة أكبر للعنصر البصري.
- فلاتر: جميع المشاهد / غير المعتمدة أو التي تغيرت / تحذيرات الحركة أو المنطق.
- دفتر ملاحظات يُخزن في `review-notes.json` بجوار السكريبت. لكل ملاحظة معرف مشهد وتوقيت بالثواني ونص وساعة الإنشاء؛ يمكن نسخ أمر إصلاح وإرساله إلى Claude.
- ملاحظات الإصلاح منفصلة عن `storyboard.json` وسجلات الاعتماد؛ لا يغير أي منها اعتماد فيديو أو مشهد.
- معاينات الفيديو القائمة في `previews/` تبقى طريقة المشاهدة في Studio. لا يُنشأ تاريخ نسخ داخل Drive إذا كان شرط التخزين «آخر نسخة فقط».

## 4. مركز التسليمات وقاعدة البيانات

مصدر القراءة المحلي هو `~/Balislam-Preview-Sync/preview-cloud-index.json` مع `bridge-delivered.json`. يُقرأ فهرس الطلبات من نسخة Git المحلية `origin/studio-handoff-queue` دون طلب شبكة بسبب فتح صفحة Studio.

- `waiting_for_mac`: طلب GitHub محفوظ محليًا لم يثبت تشغيله عبر Mac.
- `delivered`: سجل جسر Mac ينص على تنفيذ الطلب.
- `delivered_pending_review`: ملف راجعه برنامج الرفع من ناحية MD5 وأُضيف إلى الفهرس المحلي؛ لا يعني مشاهدة بشرية أو صحة الإخراج.
- `approved`: لا يمكن استنتاجه من بيانات الرفع؛ يظل في نظام اعتماد الحلقة الحالي، بقرار صاحبها فقط.

لو لم تُوجد البيانات، تظهر حالة فارغة صريحة. لا تُنشأ روابط مفترضة، ولا تعرض الواجهة أسرار `rclone` أو `.env`.

## 5. Design System

- الألوان والخطوط والمسافات وحالات التركيز على لوحة Studio نفسها فقط، دون تغيير هوية القنوات الثلاث أو ملفات إنتاج الفيديو.
- تحسين التباين، حالات لوحة المفاتيح، واجهة RTL، الشاشات الصغيرة، و`prefers-reduced-motion`.
- لا تُستخدم ألوان الحالة للإيحاء بقرار اعتماد لم يُتخذ. اللون الأخضر لنجاح التحقق الفني فقط.
- مكونات موحدة: قوائم جانبية، حقول بحث وتصفية، بطاقات تسليم، شريط حالة، دفتر مراجعة.

## 6. التشغيل الآمن لـ GitHub → Mac → Drive

- طلبات GitHub في فرع مستقل `studio-handoff-queue` وبـ commit ثابت ومسار معروف وبصمة SHA-256.
- يسمح الجسر فقط بفيديو في `previews/` أو مستندات ولوحات Storyboard محددة، ولا يستخرج ملفًا من مجلد عشوائي.
- منع Git LFS pointers والصوت المقيد وإعادة استخدام `job.id` القديم مع محتوى مختلف.
- خيار خدمة LaunchAgent جديدة عبر `scripts/setup-studio-handoff-agent.sh` بأوامر `status` و`enable` و`disable`. **لم تُثبّت على Mac بعد**؛ الفحص الجاف مطلوب قبل التفعيل.
- يظل `com.balislam.preview-sync` القديم معطلًا. لا يوجد حذف آلي للأصول أو ملفات Master.
- ينبغي ضبط صلاحيات الكتابة على فرع الطابور في GitHub، ومراجعة مصدر أي ملف يضعه Claude قبل تفعيل التشغيل غير المراقب.

## 8. سيناريو قبول كامل

1. Claude يحدد القناة والحلقة وينفذ أمرًا حقيقيًا في مساحة عمله.
2. يرفع المعاينة إلى Studio كما تقتضي قواعد القناة، ويتحقق منها.
3. إن كان سحابيًا، يرسل طلبًا دقيقًا عبر طابور GitHub؛ وإن كان على Mac، يستدعي أداة التسليم المحلية.
4. Mac ينقل الملف المحدد فقط، يتحقق من البصمة، ويسجّل نتيجة التسليم.
5. تظهر النتيجة في مركز التسليمات؛ يتم نسخ تقريرها إلى محادثة ChatGPT الخاصة بالقناة.
6. ChatGPT يراجع الملف ويرسل ملاحظات محددة بالمشهد والتوقيت؛ ويمكن حفظها في دفتر المراجعة.
7. Claude ينفذ التعديل ويحدث نفس الخانة؛ يبقى الرابط ثابتًا إذا دعم Drive الاستبدال في موضعه.
8. يراجع صاحب القناة النتيجة ويقرر اعتمادها أو طلب إصلاح جديد؛ لا ينشر النظام تلقائيًا.
9. تُختبر واجهة Studio على Mac؛ إذا فشلت الاختبارات لا يُدمج التطوير، ويُترك main دون تغيير.

## 9. العودة الآمنة

لا يغير فرع التجربة `main` ولا مساحات الإنتاج الحالية. يمكن إيقاف خدمة الجسر الجديدة لاحقًا بأمر `bash scripts/setup-studio-handoff-agent.sh disable` من نسخة المشروع المحدثة. لا تحذف ملفات المزامنة أو سجلات التسليم أثناء الاختبار.
